# ShEF Comparison and Parameterization Report
Generated on: 2026-02-09

## Overview
This report documents the differences between the original Ultra96 implementation and the ZuBoard 1CG port, as well as identifies hard-coded parameters for future automation.

## Milestone 2: Delta Analysis (u96 vs. ZuBoard)

### PMUFW (`xpfw_mod_sec.c`)
- **Header Changes:** `xilfpga_pcap.h` and `xfpga_config.h` (2019.2) replaced by `xilfpga.h` (2023.2).
- **Driver API Updates:**
    - `XCsuDma_LookupConfig` now uses `XPAR_CSUDMA_0_BASEADDR` instead of `XPAR_PSU_CSUDMA_DEVICE_ID`.
    - FPGA programming now uses `XFpga_Initialize` and `XFpga_BitStream_Load` instead of the legacy `XFpga_PL_BitSream_Load`.
- **Type Changes:** FPGA status variables changed from `s32` to `u32`.

### PMUFW (`xpfw_user_startup.c`)
- **Module Initialization:** Added `ModRpuInit`, `ModUltra96Init`, `ModCommonInit`, `ModExtWdtInit`, and `ModOverTempInit`.
- **ShEF Entry Point:** `sec_ipi_mod_init()` remains the core entry point for the security framework.

### Memory Layout & Linker Scripts
- **Shared OCM Region:** `psu_ocm_sec_buffer` (0xfffffe00, 512 bytes) is preserved across both platforms for secure handoff.
- **R5 DDR Mapping:** Significantly expanded in the ZuBoard port (`psu_ddr_0` origin 0x100000, length 0x3fefffff), providing more headroom for the Security Kernel.
- **PMU RAM:** Ported version adds `.note.gnu.build-id` and maintains the `PMU_RAM_EXT_TABLE` (0xFFDDF6E0) for persistent module data.

### Host-Side Synchronization (`host.py`)
- **Command Codes:** UART command IDs (0x01 to 0x0D) must match the Security Kernel's command parser.
- **Root Public Key:** `root_mod` (RSA-4096 modulus) must match the PMUFW's `root_pk`.
- **Attestation Size:** Expected report size of 752 bytes (0x2F0).

### Host-Side Synchronization Issues
**Finding:** During verification, the host script (`host.py`) failed to verify the attestation report because it was using an outdated RSA key (`0xdde2...`) while the firmware was correctly using the verified ZuBoard key (`0xc036...`).

**Remediation Plan:**
- Extract the verified keys into a `shef_config.py` file.
- Modify `host.py` to import parameters from this config file rather than hard-coding them.
- This ensures that a single update to the key generator (Milestone 4) will update both the hardware and the host script simultaneously.

### Cryptographic Keys (Critical for Automation)
- **PMUFW `root_pk`:** Hard-coded RSA-4096 public key in `xpfw_mod_sec.c`.
- **Security Kernel `XSECURE_AES_KEY`:** Hard-coded in `security_kernel.h`.
- **Security Kernel `XSECURE_IV`:** Hard-coded in `security_kernel.h`.
